# Análisis Funcional - API de Gestión de Usuarios

## Módulos identificados
1. **Autenticación**
   - Login (generación de tokens)
   - Logout (invalidación de token)
   - Refresh (renovación de token)

2. **Usuarios**
   - CRUD de usuarios
   - Gestión de permisos por roles

3. **Perfiles**
   - Información extendida de usuarios
   - Gestión de archivos (foto en S3)

## Actores y Roles
| Rol** | **Permisos** |
|-------|--------------|
| ADMIN | Acceso total a todos los endpoints, gestión de usuarios |
| USER  | Solo acceso/modificación de su propio perfil |
| GUEST | Solo puede autenticarse (login) |

## Flujos por módulo

### Autenticación
**Principal (Login):**
1. POST /api/auth/login
2. Validación email/password
3. Generación de tokens (24h access, 7d refresh)

**Alternativos:**
- Credenciales inválidas → HTTP 401
- Usuario inactivo → HTTP 403

**Errores:**
- ⚠️ Comportamiento con refreshToken expirado no definido

### Usuarios
**Principal (Creación):**
1. POST /api/users (solo ADMIN)
2. Validación email único
3. Hash de password
4. Creación con active=true

**Alternativos:**
- Email duplicado → Error
- Password inválido → Error

**Errores:**
- ⚠️ No se especifica política para cambios de rol

### Perfiles
**Principal:**
- GET/PUT /api/users/:id/profile
- Gestión de metadatos y archivos

## Reglas de negocio
1. RN-001: Email único en sistema
2. RN-002: Password mínimo 8 chars (1 mayúscula, 1 número)
3. RN-003: Usuarios inactivos no pueden autenticarse
4. RN-004: RefreshToken se invalida en logout
5. RN-005: ADMIN no puede autoborrarse
6. RN-006: Paginación máxima 100 registros

## Precondiciones globales
- Header `Authorization: Bearer <token>` requerido (excepto login)
- Content-Type: application/json
- Fechas en ISO 8601 UTC

## Ambigüedades detectadas
1. ⚠️ Comportamiento con refreshToken expirado no documentado
2. ⚠️ Cambio de rol de usuario no especificado en PUT /users/:id
3. ⚠️ Política de intentos fallidos de login/bloqueo no definida
4. ⚠️ No se especifica formato/tamaño máximo para foto de perfil

## Resumen ejecutivo
API RESTful para gestión de usuarios con:
- Autenticación JWT (access + refresh tokens)
- CRUD de usuarios con control por roles (ADMIN/USER/GUEST)
- 3 módulos principales (Auth, Users, Profiles)
- 6 reglas de negocio claramente definidas
- ⚠️ 4 áreas requieren clarificación (seguridad y edge cases)
- Estructura de respuestas JSON estandarizada
- Precondiciones técnicas consistentes
