# Análisis Funcional del Sistema de Login de Usuarios

## Módulos identificados
1. **Autenticación de usuarios**
   - Ingreso de credenciales (email y contraseña).
   - Validación de credenciales.
   - Manejo de intentos fallidos.
2. **Recuperación de contraseña**
   - Envío de enlace de recuperación por correo electrónico.
3. **Acceso al dashboard**
   - Acceso permitido tras autenticación exitosa.

## Actores y Roles
1. **Usuario**
   - Persona que ingresa sus credenciales para acceder al sistema.
2. **Sistema de autenticación**
   - Aplicación o componente que verifica y valida las credenciales ingresadas.
3. **Servidor de correo**
   - Sistema encargado de enviar el enlace de recuperación de contraseña.

## Flujos por módulo
### Autenticación de usuarios
**Flujo principal (F1):**
1. El usuario accede a la pantalla de login.
2. Ingresa su correo electrónico y contraseña.
3. El sistema valida las credenciales ingresadas:
   - Si son correctas, se redirecciona al dashboard.
   - Si son incorrectas, muestra un mensaje de error.

**Flujo alternativo (F2 - Cuenta bloqueada):**
1. Después de 3 intentos fallidos consecutivos, el sistema bloquea la cuenta del usuario.
2. Se muestra un mensaje indicando que la cuenta está bloqueada.

**Errores (E1):**
- Si los datos ingresados no cumplen un formato correcto (ejemplo, email inválido), se muestra un mensaje indicando el error.

---

### Recuperación de contraseña
**Flujo principal (F3):**
1. El usuario selecciona la opción "Recuperar contraseña".
2. Ingresa el correo electrónico asociado a su cuenta.
3. El sistema envía un enlace de recuperación al correo proporcionado.
4. El usuario utiliza el enlace para establecer una nueva contraseña.

**Errores (E2):**
- Si el correo ingresado no está asociado a ninguna cuenta:
  - Se muestra un mensaje indicando que no se encontró un usuario con ese correo.

---

### Acceso al dashboard
**Flujo principal (F4):**
1. Una vez que las credenciales son validadas con éxito, el sistema redirige al usuario al dashboard.

**Errores:**
- ⚠️ Comportamiento no especificado en caso de falta de acceso a las funciones de dashboard o permisos denegados.

## Reglas de negocio
1. Un usuario será bloqueado si ingresa la contraseña incorrectamente 3 veces consecutivas.
2. La cuenta bloqueada no puede ser utilizada para iniciar sesión hasta que se desbloquee (⚠️ Se asume que será mediante recuperación de contraseña, pero no se especifica explícitamente).
3. El enlace de recuperación se envía únicamente al correo registrado en el sistema asociado a la cuenta del usuario.
4. ⚠️ No se específica la duración del bloqueo (¿es permanente?) ni si se notificará al usuario sobre ello.

## Precondiciones globales
1. El usuario debe estar registrado con un correo electrónico válido antes de intentar iniciar sesión.
2. El sistema debe soportar intentos de login y recuperación de contraseña.
3. La infraestructura debe contar con un servicio de envío de correos operativo y funcional.

## Ambigüedades detectadas
- ⚠️ No se detalla cómo se desbloquea una cuenta bloqueada (¿es automático después de un tiempo? ¿requiere acción manual?).
- ⚠️ No se especifica el tiempo de expiración del enlace de recuperación de contraseña.
- ⚠️ No se menciona si el sistema valida solamente que el email exista o también si ha sido verificado previamente.
- ⚠️ No está claro cuál es el formato o nivel de seguridad requerida para las contraseñas (longitud mínima, caracteres especiales, etc.).
- ⚠️ No se define comportamiento en contextos de múltiples intentos simultáneos desde diferentes dispositivos.

## Resumen ejecutivo
El análisis funcional ha identificado tres módulos principales en el sistema de login de usuarios: autenticación, recuperación de contraseña y acceso al dashboard. Los flujos principales están relativamente bien definidos, aunque se detectaron varias ambigüedades en el manejo de errores y desbloqueo de cuentas bloqueadas. Las reglas de negocio aún carecen de ciertos detalles importantes, como aspectos relacionados con la seguridad (expiración de enlaces de recuperación, reglas de contraseñas) y manejo de situaciones específicas como logins concurrentes. Se recomienda precisar estos puntos para garantizar un diseño más robusto y consistente.
